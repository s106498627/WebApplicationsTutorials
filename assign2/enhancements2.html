The Cart

I was inspired to make the cart act this way from an app called OpenNutriTracker, which keeps a daily list of what you eat. In this app you add items with the + icon and it opens a submenu for all sorts of options. I was able to recreate this in a simple way in the cart. I thought it appropriate as there are only 3 products, so the selection process is simple. I use the HTML itself to keep track of how many items were in the cart via the number of `cart-item` divs by getElementByClassName, and then I use this to renumber the items in the cart when one is deleted. This way I do not have to track the cart in JS and replicate it in the HMTL, ie 2 points of failure rather than 1. The cart items are implemented as a template, which the JS copies when the add item button is pressed. The remove button also hides when there is 1 item in the cart. I had particular problem with this because no matter what I did, the remove button would not hide when there was only 1 item in the cart. I found this article which explained the hidden attribute is "visibly weak" and must be overridden with display: none !important in CSS. Feels like a bit of a hack to me, but it does work. The tricky part was getting all the fields to renumber correctly when an item was deleted. I had to use the querySelector> method to find a data-field (data-* is reserved for programmer-defined attributes to carry information) I placed in each of the inputs for each cart item so I could change the name attribute to match the new number.


VueJS Rewrite of the Enquire Form


I rewrote the enquire form using VueJS. I work full-time as a Software Engineer and use VueJS somewhat frequently at work (my team is primarily working on the core engine) so I felt comfortable using it for this enhancement. I used the VueJS forms guide as a basis for my new form. Using v-model was a very handy technique to pass through JS variables and update them on the fly without having to go through the lengthy document.getElementBy* each time you wanted an up-to-date view of the input. I alo used the VueJS event handling guide to learn how to handle submit events in the exact way needed for the enhancement. As most websites use VueJS or ReactJS these days, I thought this was a good enhancement to make. It was interesting to see how I can integrate new-age web technology on a more classical LAMP stack website. The other clear advantage of this is I can use TypeScript, which is essentially JavaScript with strict types. I despise dynaic typing because of the implicit type casting that causes a multitude of hard to find bugs as well as the IDE engine not being able to deduct the type meaning I cannot use code completion, and I was happy with the speed at which I could write TypeScript opposed to JavaScript. Check .github/workflows/deploy.yml as this is how I am deploying to Mercury. I am Using GitHub Actions to build the VueJS code and copy it to the Mercury server.
